Amazon OpenSearch Serverless: Derived Source

Post 01 of 03
Less storage overhead on OpenSearch, no trade-offs
AWS To Review
Amazon OpenSearch Serverless
Derived Source Storage Optimisation Serverless
Amazon OpenSearch Serverless now supports Derived Source, and it is a useful one for teams managing data-heavy workloads. The problem it solves is straightforward. OpenSearch has historically stored a separate copy of each document's source fields alongside the indexed data. That duplication adds up fast on large collections, and you end up paying for storage of data you already have in the index. Derived Source changes that. Instead of maintaining a separate source copy, OpenSearch reconstructs the _source field on the fly from the values already stored in the index. Same query behaviour, same results, less storage. For most workloads the performance impact is negligible. For collections with large documents or high cardinality fields, the storage savings can be significant, and on Serverless where you pay for what you use, that feeds directly into cost. This is worth reviewing if you are running OpenSearch Serverless for log analytics, search, or observability pipelines. The efficiency gain is real and the setup change is minimal. #AWS #AmazonOpenSearch #CloudStorage #DataEngineering #AWSManaged

AWS Agent Registry: Governing AI at Scale

Post 02 of 03
AWS Agent Registry is in preview and it is worth paying attention to
AWS To Review
AWS Agent Registry · Amazon Bedrock AgentCore
Public Preview AI Governance MCP + A2A Sydney Available
AWS launched Agent Registry in preview this week. It is part of Amazon Bedrock AgentCore and it addresses a problem that is becoming very real for teams scaling AI workloads. The problem is agent sprawl. As organisations deploy more AI agents across teams, the questions get harder to answer fast. What agents are actually running? Who owns them? Has this capability already been built somewhere else in the org? Without a central system, teams rebuild things that exist, compliance gaps grow, and nobody has full visibility into what is running in production. Agent Registry gives you a governed catalog for every agent, tool, MCP server, and agent skill across your organisation. It works across AWS and non-AWS environments, so it covers the full picture rather than just what sits inside one platform. Every record goes through an approval workflow before it becomes discoverable. Search is hybrid, so a query for one term will surface related capabilities even if they are named differently. The audit layer is worth calling out. CloudTrail covers all registry access and admin actions, which matters for any organisation with compliance requirements around AI systems. It is available now in preview in Sydney, which is relevant for Australian teams. For companies deploying agents beyond a handful of use cases, getting governance in place early is considerably easier than dealing with it after the fact. #AWS #GenerativeAI #AmazonBedrock #AIAgents #AgentCore #CloudAI

AWS Security: AI-Powered Defense at Scale

Post 03 of 03
How AWS is using AI to defend customers before threats emerge
AWS To Review
AWS Security · AI-Powered SecOps
Threat Intelligence Security Automation Log Analysis
AWS published a detailed look at how they use AI to defend customers at scale, and there is a lot in it worth understanding beyond the headline. The part that stands out most: their AI-powered log analysis system has meaningfully reduced the time their SecOps engineers spend on manual triage. Log analysis is one of the biggest drains on any security team. When volume is high, human review becomes the bottleneck and things get missed. Automating the first pass is not a luxury, it is a requirement for running security at scale. The broader principle in the post is one we apply with clients. Waiting for an incident to understand your security posture is the wrong approach. The organisations that handle this well have shifted from reactive to continuous: automated monitoring running in the background, anomaly detection surfacing the signals that matter, and response playbooks that trigger without someone needing to notice first. Most of the teams we work with on AWS are not starting from zero on security. The gap is usually not the tools, it is whether those tools are configured to actually catch the right things and whether anyone is watching when they do. If your AWS environment does not have that monitoring and automation layer working properly yet, this is a good moment to address it. #AWS #CloudSecurity #SecurityAutomation #DevSecOps #AWSPartner
