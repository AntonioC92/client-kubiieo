Amazon EMR: Apache Spark 4.0.2 Generally Available

Post 01 of 03
Spark 4.0.2 is now GA across all three Amazon EMR deployment modes
AWS To Review
Amazon EMR · Generally Available
GA · All EMR Modes Iceberg v3 Row-Level FGAC Real-Time Streaming
Apache Spark 4.0.2 is now generally available on Amazon EMR, and it is available across all three deployment modes: on EC2, on EKS, and Serverless. That matters because a lot of teams have fragmented data infrastructure. Some workloads run on managed EC2 clusters, others are containerised on EKS, and Serverless handles the more unpredictable jobs. Historically, a major Spark version upgrade could mean different timelines and different complexity depending on which deployment model you were on. That gap is closed now. The upgrade itself is substantive. ANSI SQL compliance with proper VARIANT data types simplifies pipeline logic that previously required workarounds. Row and column-level fine-grained access control is now built in, which is the governance requirement that was previously a significant engineering effort to implement correctly. Apache Iceberg v3 table format brings the open table standard up to date, and the streaming improvements reduce latency for real-time data applications. For teams running compliance-sensitive data pipelines on EMR, this is the version that makes governance the default rather than something you layer on afterwards. If your data infrastructure runs on EMR and you have not looked at what Spark 4.0.2 means for your current setup, it is worth doing that assessment now. #AWS #DataEngineering #ApacheSpark #AmazonEMR #CloudManagedServices

Amazon SageMaker: NVIDIA Blackwell P6-B200 Generally Available

Post 02 of 03
NVIDIA Blackwell B200 GPUs are now available on Amazon SageMaker Notebook Instances
AWS To Review
Amazon SageMaker · Generally Available
US East · GA 8× Blackwell GPUs 2× Training Speed 1440 GB HBM3e
P6-B200 instances are now generally available on Amazon SageMaker Notebook Instances in US East (N. Virginia). The spec is worth understanding in full. Each instance carries 8 NVIDIA Blackwell B200 GPUs with 1,440 GB of HBM3e GPU memory, paired with 5th Gen Intel Xeon Emerald Rapids processors. AWS is quoting up to 2x better AI training performance compared to P5en instances. The part that matters most is how this changes what foundation model training looks like in practice. P6-B200 is not aimed at inference or light experimentation. This is the instance class for teams that are actually training or fine-tuning large models, running evaluation loops at scale, or handling workloads where GPU memory is the constraint that determines what is even possible. What makes the SageMaker Notebook Instances context significant is that it wraps that raw compute capacity in a managed environment. You are not building and maintaining the infrastructure underneath it. The operational overhead of running this class of compute drops considerably, which changes the calculation for teams that have been deferring serious model work because of infrastructure complexity. If you are planning AI training workloads or evaluating whether your current infrastructure is the right fit, this is worth looking at now rather than when you hit the ceiling. #AWS #NVIDIA #Blackwell #AmazonSageMaker #GenerativeAI #MLInfrastructure

AWS Security: Supply Chain Attacks and Well-Architected Guidance

Post 03 of 03
AWS has updated its Well-Architected guidance for software supply chain security, and the timing is not coincidental
AWS To Review
AWS Security · Well-Architected
Supply Chain Security Amazon Inspector Well-Architected
AWS published updated Well-Architected best practices for software supply chain security this week. The update comes in the context of a series of confirmed npm supply chain attacks over recent months, including Shai-Hulud, Chalk/Debug, one exploiting tea.xyz tokens, and most recently axios. Several of those attacks were caught through a combination of community effort, Amazon Inspector, and the Open Source Security Foundation. The fact that they were caught is the good news. The more sobering part is that the window between a malicious package being published and being in production somewhere is extremely short. The core principle in the updated guidance is one that applies directly to AWS workloads. Treating third-party packages as trusted inputs is a risk. Every dependency in your build pipeline is a potential attack surface. The organisations that handled these incidents well had Inspector running continuously, IAM locked down across build and deploy pipelines, and dependency audit processes that operated on a continuous rather than periodic basis. For most teams, the gap is not awareness. Most engineers understand supply chain risk in the abstract. The gap is whether the controls are actually in place and configured correctly, and whether anyone will notice if a malicious package makes it into the pipeline. This is a good moment to look at whether your AWS security posture covers the supply chain layer properly. #AWS #CloudSecurity #SupplyChain #AmazonInspector #WellArchitected #DevSecOps
