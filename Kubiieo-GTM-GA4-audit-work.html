Summary for Baz

I've built the tracking setup that the Google Ads campaigns depend on. The job of this work is simple to state. Before we put real money into ads, we need to know which ad clicks actually turn into enquiries. Without that, we'd be guessing, and the ads would keep bringing traffic that never converts. So the stack I've built has three jobs: respect the visitor's cookie consent, track which ad each visitor came from, and count it when someone fills in the contact form or clicks the phone number.

Three pieces are already live on the site right now. A consent default (sets analytics and ads to denied by default, so nothing fires before the visitor says yes), a Google Ads attribution link (remembers which ad a visitor clicked on across pages), and a form-submit listener (catches every contact form submission and sends the details into our analytics pipeline). Six more tags are fully built and sitting paused inside Google Tag Manager. They are ready to go, waiting only on two small unlocks from Baz's side.

What's left is not technical difficulty, it is two external things Baz controls. First, an admin login to the WordPress site so I can turn off an old piece of tracking code that would cause our numbers to double if I left it running. Second, resolving the Google Ads account situation so I can create the two conversion actions that the paused tags are waiting to send data to. Once those two things are cleared, I can finish the build in about 90 minutes and we are ready to launch the campaigns laid out in the March strategy document.

01

Where we started, the audit findings

Before building anything, I checked what was already in place on kubiieo.com. The short answer was that if we had launched the Google Ads campaigns on the existing setup, Google would have had no way of knowing which ad clicks actually became enquiries. It would have kept sending traffic based on who was clicking, not on who was converting. That is exactly the risk the strategy document flagged in March.

What the baseline looked like
LayerState when I started
Google Tag ManagerContainer GTM-TV9VXWHD was installed correctly but completely empty. zero tags, zero triggers, zero rules. It loaded on every page and did nothing.
Google Analytics 4Firing via a hardcoded gtag.js snippet injected by the HFCM (Head Footer Code Manager) WordPress plugin, running outside of GTM. Basic event tracking only, no custom conversions, no key events marked.
Google Ads trackingNo AW-… conversion tag anywhere on the site, no Conversion Linker, no Enhanced Conversions wiring.
Consent Mode v2Not implemented. No default consent state set. No CMP banner installed.
Form conversion trackingThe contact page uses Elementor Pro Forms which submit via AJAX, the standard GTM form submit trigger doesn't fire on these. No data was being captured on form submissions at all.
GA4 data retentionDefault 2 months. Reports older than 8 weeks would have been lost.
Google signals & Enhanced ConversionsOff. Demographic insights and modelled conversions unavailable.

In plain terms, we would have been paying Google for clicks without telling it which of those clicks actually led to a real consultation request. At the $10 to $18 AUD per click the strategy projected for the main keywords, the budget would have run out before we could learn which ads were working.

What I built in Google Analytics 4

Alongside the tag manager work, I made six changes to the Google Analytics 4 settings so the data is kept long enough, made richer, and kept clean of personal information. These are standard hygiene items that were not in place before.

04

What I tested and confirmed working

I did not just build this and hope for the best. I ran live tests against kubiieo.com to confirm each piece does exactly what it should. Here is what I verified in those tests.

Page load On both kubiieo.com/ and kubiieo.com/contact/, all three live tags fire correctly on every page view: Consent - Default v2, Ads - Conversion Linker, and DL - Elementor Form Bridge. Tags not fired: none.
Consent ordering The Consent - Default v2 tag fires on the Consent Initialization event, before any other tag. That ordering is load-bearing, it means when the Google Ads and GA4 tags eventually go live, they already see the consent defaults (denied) rather than running unconstrained.
Form submit end-to-end Simulated a full form submission on /contact/ with test email and phone. The dataLayer received a kubiieo_form_submit event with a populated payload: form_name: "elementor_form", form_id: "New Form", form_location: "/contact/", user_email: "antonio.test@kubiieo.com", user_phone: "+61412345678". The downstream GA4 and Ads conversion tags are correctly wired to fire off this exact event, they just need their unpause conditions cleared.
PII hygiene Email addresses are captured by the form bridge but trimmed and lowercased before dataLayer push. Phone numbers are stripped of non-digit characters. This is the format Google Ads Enhanced Conversions for Leads expects.
Tag Assistant debug session Two separate debug sessions (home page and contact page) confirmed identical behaviour, the same three tags fire on every page view, with no unexpected tags, no missing tags, no console errors.

What's blocking progress, Baz's next actions

Two things are currently blocking the last piece of the build. Both sit on Baz's side. As soon as either one is cleared, everything it unlocks gets done quickly.

1. WordPress admin access for kubiieo.com

An administrator account on the WordPress backend. This unlocks five items in one go:

  • Disabling the HFCM legacy GA4 snippet, which then lets me unpause the GA4 Configuration tag in GTM and start proper conversion event flow into GA4.
  • Installing a Consent Management Platform (I recommend Complianz for AU + EU coverage), essential for Consent Mode v2 to have anything to update defaults against, and required for GDPR compliance on any EU traffic from Sean's LinkedIn outreach.
  • Disconnecting or uninstalling the dormant Site Kit by Google plugin, currently a latent risk of triple-injection if anyone connects it to Analytics or Ads.
  • Adding reCAPTCHA v3 to the Elementor contact form, prevents bot submissions from polluting Smart Bidding once paid traffic arrives.
  • Fixing or confirming the US-format 1-800-356-8933 phone number that appears on every page, worth sanity-checking against the AU positioning the ads will establish.

Estimated time once access is granted: about 60 minutes of my time to complete all five WordPress-side items plus the corresponding GTM unpauses and a follow-up smoke test.

2. Google Ads account, fixes on Baz's side and account access

Baz mentioned there are issues on his side with the Google Ads account that need to be resolved before we can progress. Once those are cleared, what I need to complete the Ads-side integration is:

  • Access to the Kubiieo Google Ads account at Standard or higher permission level so I can create conversion actions, manage auto-tagging, and link it to GA4.
  • Confirmation that auto-tagging is enabled in the Ads account settings, so gclid populates on every ad click. Without this, Enhanced Conversions and offline conversion imports don't work.
  • Permission to create two conversion actions. Consultation Request (category: Submit lead form, count: One) and Phone Call Click (category: Phone call lead, count: One). Both pointing at the events the GTM tags are already wired to send.
  • Enabling Enhanced Conversions for Leads in the Ads goal settings so the hashed email and phone we're already collecting on form submit get mapped to conversions.
  • Linking the Google Ads account to the GA4 property (this enables audience sharing for remarketing and imports key events as conversion signals).

Estimated time once access lands: about 30 minutes of my time to create the two conversion actions, copy the AW- IDs into the paused GTM tags, unpause them, and run a conversion diagnostics check in the Ads UI.

3. IP addresses for internal traffic filter (minor)

A short list of IPs, Kubiieo office, Baz's home, anyone at the team who's regularly on the site, so I can configure a GA4 internal-traffic filter and stop internal browsing from inflating the numbers Sean and I will be judging campaign performance against.

Estimated time: 10 minutes once the IPs are supplied.

What happens the moment these unlocks land

Here is exactly what I will do as soon as Baz gives me the WordPress login and the Google Ads account situation is sorted.

Phase 1, WordPress side (about 45 minutes)
  1. Log into WordPress, disable the HFCM Google Analytics snippet.
  2. Verify in GA4 DebugView that page_view events stop arriving from the hardcoded snippet.
  3. In GTM, unpause the GA4 Configuration tag and all three GA4 Event tags (generate_lead, click_to_call, click_to_email). Publish as v4.
  4. Confirm in DebugView that events resume flowing, now from GTM, at equivalent volume.
  5. Mark generate_lead as a Key Event in GA4 Admin so Google Ads can import it.
  6. Install Complianz (or CookieYes), configure Consent Mode v2 with denied defaults, test that consent acceptance correctly updates the defaults set by our GTM tag.
  7. Disconnect Site Kit (or uninstall). Enable reCAPTCHA v3 on the Elementor form. Confirm / fix the phone number.
Phase 2, Google Ads side (about 30 minutes)
  1. In the Ads account, confirm auto-tagging is on.
  2. Create the Consultation Request conversion action (category: Submit lead form, count: one, attribution: data-driven).
  3. Create the Phone Call Click conversion action (category: Phone call lead, count: one).
  4. Enable Enhanced Conversions for Leads in Goals → Settings → Customer data.
  5. Link Google Ads to GA4 via GA4 Admin → Product Links.
  6. Copy the AW- conversion IDs and labels back into the two paused Ads conversion tags in GTM. Unpause them. Publish v5.
  7. Create the three remarketing audiences in GA4 (Form submitters, Engaged visitors, Services page viewers), they'll start populating within 24 hours.
  8. Run conversion diagnostics in Google Ads to confirm conversions are recording and Enhanced Conversions are matching.

Total time once unblocked is roughly 75 to 90 minutes of focused work. After that the setup is complete and the campaigns from the March strategy can go live with full visibility into which ads are generating real enquiries.
